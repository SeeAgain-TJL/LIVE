# Exterior Batch 1.2 · 验收记录

日期：2026-11-04。基线为 `1b41f5f`（Batch 1.1），优化版为本交付。只修改星系外部的渲染与取证代码；Pine Forest、星球内部、档案 schema 和导航接口保持原有实现。

## 测量方法

在同一台 Windows 11 / Core 5 220H / Intel Graphics D3D11 机器上，以安装版 Google Chrome headless、1600×1000 CSS 像素、设备 DPR 1.5 跑独立生产服务。每个案例使用新浏览器上下文、禁用 HTTP 缓存、固定种子、相同视口和相机书签，写入隔离的外观压力样本。档案原文在进入、返回与换档后核对。第一轮按高、中、低和 5、20、50 颗测试，每例先基线后优化；第二轮反转档位、数量及同例的版本顺序。保留整机 CPU、可用内存和每个采样窗口，不以单轮结果代表所有机器。

- **首个可交互帧**：以导航时钟为起点，取实际 WebGL 绘制、相机控制器处于 idle、星球标签已挂载的第一帧。两版都用同样的标志。浏览器专项另在暂停 Worker 时做真实滚轮输入，确认投影在完整贴图之前已响应。该指标不等于点击后的输入延迟，也不使用首次贴图时间替代。
- **完整贴图**：取第一帧外部贴图就绪。基线等待全部挂载星球的手选档贴图；优化版等待初始视角预算内的当前目标档，并允许离屏星球无贴图、远景采用更低档。因此这是各版当前视图就绪时间；两版生成的高精度贴图数量不同。
- **运动**：分别做右键平移、滚轮放大再缩回、切离并切回画质、通过列表按钮触发快速飞行至实际档案路由，再返回所属星系。平移及缩放都记录标签在中途确实移动。FPS 是 rAF 平均帧间隔的倒数；p95 取同一采样窗口的帧间隔分位数。
- **GPU**：同一探针在两版区分离屏星云和默认 framebuffer，使用 WebGL disjoint timer query，缺失样本不填零。透明混合 draw 包括大气、云、环、星点、轨道和背景合成；它是计数，不能推断每项各自耗时。探针不包含浏览器所有合成、调度和显示等待。资源用静止窗口末的 `gl.info` 和当前 LOD 状态采样；行星贴图容量按 RGBA8 + mip 链估算。

固定全景中，两版三档的纹理对象数都是 5 颗 11 张、20 颗 41 张、50 颗 101 张。5 颗的高/中/低档几何体为 31/31/27，优化后相同；20 颗由 80/80/61 变为 76/76/61，50 颗见下节。纹理数量不反映单张尺寸。

在固定全景中，50 颗都可见，两版渲染器均报 101 张纹理；高/中档优化版为 40 组低档 + 10 组中档，低档为 50 组低档。高档的估算行星贴图容量减少约 **90%**。这不是驱动报告的显存；新旧贴图切换期间的短暂共存、离屏目标和 CPU 像素缓存另计。Chrome 专项另从一颗可见星球飞向离屏星球，确认旧贴图退出及目标升到高档。

## Chrome 视觉核对

检查了两版三档的 18 张全景及 10 张固定相机的高档近景。五类近景各有一组已提交的高档行星贴图：岩石撞击坑、海陆/亮云、气态条带、冰面裂纹和多层细星环都可辨识，无明显近景材质回退。50 颗全景中位置、轮廓和背景构图保留；远景海洋星的亮云减少，符合较低档贴图/云层的设计差异。近景定格不能覆盖所有跨阈值运动；实现通过升降档滞回、候补贴图保留及淡出小尺寸大气来减轻突变。

## 回归

`npm.cmd run lint`、`npm.cmd run typecheck`、`npm.cmd test`（48/48）、`npm.cmd run build`、安装版 Chrome 的 `npm.cmd run test:e2e`（30/30，4.3 分钟）均通过。专项覆盖暂停 Worker 时可缩放、离屏目标飞入升档、旧贴图释放、五类换档资源稳定和 Worker 不可用时的回退。初次专项的一次滚轮事件仅移动标签约 0.55 CSS px，触发大于 1 px 的断言；最终用三次滚轮，并保持 Worker 暂停至显式恢复。该次失败的 trace 与最后一次全量 JSON 报告分别保存在本机 `artifacts-local/exterior-batch-1.2/browser-initial/` 和 `artifacts-local/exterior-batch-1.2/browser-full.json`。

未测实际手机 GPU、长期运行或 headed Chrome 的合成轨迹。下一阶段若有明确的运动帧时目标，建议先用有窗口 Chrome 对同一组 50 颗操作做 compositor、GPU 和换档长帧的联合采样，再决定是否调整背景或透明层。
