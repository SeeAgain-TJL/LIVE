# 技术决策记录

## 2026-10-29 · D014：显式选择与非模态阅读抽屉

V3 任务 A 修复的关闭问题来自“唯一结果自动选中”，不是 × 的点击冒泡。选择只由用户操作或保存结果设置，关闭一律清空；筛选变化清空选择，避免不可见记忆继续展示。详情是固定的非模态抽屉，允许桌面继续选择场景/列表，手机使用底部抽屉；正文独立滚动，头部关闭与底部编辑/删除保持可达。Escape 检查原生 dialog 是否打开，先交由编辑/删除弹窗处理；关闭后恢复可用触发控件的焦点。

用真实浏览器回归单球关闭、双球切换和编辑后刷新，修复前先确认断言失败。刷新不再自动展开仅有的一条记忆，测试须通过真实选择重新打开。

## 2026-10-29 · D015：局部布局与相机控制改进，不升级数据格式

星球内部改为紧凑简介、分组工具栏、全宽场景；资料操作收进原生 details，避免常驻资料栏和第二个 Canvas。字号使用页面局部变量（正文 16px / 控件 14px / 辅助 13px），避免改变宇宙主页。引导者保留两个主要操作，高级查找按需展开，阅读详情时隐藏。

相机飞行与 OrbitControls 共用控制目标，飞行完成后停止强制写相机。全景按球体边界和宽高比取景，单球居中、聚焦距离至少 8、手动最近距离 6.5，选中比例限制为 1.1。Html 使用独立 portal；低性能模式减少几何细分但保留可读的类型标识。海量数据分页仍待后续，不把简化渲染当作完整性能验收。

不更改 schema、存储键或媒体数据库。媒体记忆删除必须在同一次元数据提交中移除 Memory 和关联 Media，再删除 Blob；否则现有校验会拒绝孤儿引用。媒体 object URL 由 effect 的局部变量在卸载时释放，避免通过卸载组件的 setState 清理资源。

## 2026-10-29 · D016：浏览器回归使用独立生产端口和固定媒体素材

Playwright 默认在 3100 端口启动本轮 build，禁止复用已有服务，避免测到旧构建或开发 HMR 状态；需要其他端口可设置 `PLAYWRIGHT_PORT`。日常开发地址仍为 3000，同源存储保持原样。测试使用隔离浏览器上下文，正常通过表单写入，不清理用户站点数据。

照片/视频采用仓库内原创合成 PNG 与 VP8 WebM 小文件，并实际验证解码和播放；不依赖外部素材下载或每次运行的 Canvas 捕获帧调度。当前 headless Chrome 在部分场景捕获不到帧会生成只有头部的 WebM，不应将这种无效素材误判为存储失败。

媒体删除会先提交元数据，再异步清理 Blob，确认弹窗在两者完成后关闭。交互验收以确认弹窗关闭为完成信号，然后刷新和验证 Blob；不能仅凭详情已消失就刷新页面，中断尚未完成的删除。

## 2026-10-28 · D012：星球内部默认使用 3D 记忆球，列表作为辅助模式

星球档案原有的结构化阅读与 CRUD 继续保留，但 `/planet/[id]` 的默认体验改为 R3F 记忆球空间。每个球体只接收已经筛选好的强类型 Memory/Media props，业务搜索与持久化仍留在客户端页面和 provider；详情正文独立在 HTML 面板中，避免把长文本贴到球面。引导者是原创 CSS/2D 组件，使用确定性的本地搜索、筛选和预设话术，不接入模型服务，也不上传私人内容。

## 2026-10-28 · D013：用确定性布局和渐进降级控制记忆数量

记忆球使用纯函数螺旋布局，选中后由相机平滑对准目标；大于 80 条记忆、低性能设备或用户选择 LOW 时减少几何细分和标签。列表模式提供可访问的键盘管理路径。后续数据量更大时再引入分页/虚拟化，避免本轮引入与当前阶段无关的基础设施。

## 2026-10-28 · D011：媒体采用 IndexedDB，元数据采用 localStorage v2

第二阶段继续使用明确标注的浏览器开发存储。文本、星球资料和媒体元数据保留在版本化 localStorage 快照中；照片与视频 Blob 写入 IndexedDB，避免 base64 放大 JSON 并突破 localStorage 配额。v1 快照读取时补齐 `media` 与 `mediaIds` 后按 v2 保存，正式版本再替换为 Prisma + 私有 S3/R2 仓库接口。当前方案只保证同一浏览器配置的刷新持久化，不声称账号、加密或跨设备安全。

## 2026-10-28 · D001：先完成探索，再铺开基础设施

仓库为空，无既有 HTML/截图/代码。按用户优先级新建 Next.js App Router、React、strict TypeScript 工程；第一轮建立真实 3D、档案路由和可保存的创建入口。为了让闭环可验证，提前实现最小文字记忆和 JSON 导出。账号、媒体和高级探索不阻塞第一轮。

## D002：React Three Fiber + Drei，程序材质起步

R3F 与 React 生命周期协作，Drei 提供成熟 OrbitControls/Html。本地程序纹理避免贴图服务依赖、授权与外部资源加载失败；星环和大气用轻量 shader。它们是原型级材质方案，不声称达到 NASA 摄影级品质。后续根据实际 GPU 数据换用经过许可的高分辨率贴图、色彩管理与更精细阴影。

镜头位置与观察目标共同插值，避免只移动相机造成突兀旋转。暂不引入 GSAP 和后处理依赖；只有出现真实动画需要再增加。

## D003：浏览器本地仓库明确标为开发方案

无账号、PostgreSQL 或 S3 配置，先用 localStorage 提供创建/重访闭环。它有容量、同源、隐私与易清理限制，不是正式云存储。所有页面明确标识「本地开发版」。资料默认 `visibility=private` 只是领域默认值，**不代表当前具有服务端权限保护**。

先引入 repository 接口、schema 版本、字段校验、revision 和上一版快照，避免以后难以迁移。跨标签页检查不是数据库事务。正式后端接入时本地同步接口需要改为异步应用服务；3D 保持纯 props 接口。

## D004：选择 PostgreSQL + Prisma 作为后续唯一 ORM

关系数据适合长期演化，Prisma 类型和迁移工具便于维护。当前只在架构文档规划模型，未安装 Prisma、未连接数据库，不添加无实际作用的假 API。正式接入时先设计并验证迁移、所有权和导出/恢复流程。
