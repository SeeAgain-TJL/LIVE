# 技术决策记录

## 2026-10-28 · D001：先完成探索，再铺开基础设施

仓库为空，无既有 HTML/截图/代码。按用户优先级新建 Next.js App Router、React、strict TypeScript 工程；第一轮建立真实 3D、档案路由和可保存的创建入口。为了让闭环可验证，提前实现最小文字记忆和 JSON 导出。账号、媒体和高级探索不阻塞第一轮。

## D002：React Three Fiber + Drei，程序材质起步

R3F 与 React 生命周期协作，Drei 提供成熟 OrbitControls/Html。本地程序纹理避免贴图服务依赖、授权与外部资源加载失败；星环和大气用轻量 shader。它们是原型级材质方案，不声称达到 NASA 摄影级品质。后续根据实际 GPU 数据换用经过许可的高分辨率贴图、色彩管理与更精细阴影。

镜头位置与观察目标共同插值，避免只移动相机造成突兀旋转。暂不引入 GSAP 和后处理依赖；只有出现真实动画需要再增加。

## D003：浏览器本地仓库明确标为开发方案

无账号、PostgreSQL 或 S3 配置，先用 localStorage 提供创建/重访闭环。它有容量、同源、隐私与易清理限制，不是正式云存储。所有页面明确标识「本地开发版」。资料默认 `visibility=private` 只是领域默认值，**不代表当前具有服务端权限保护**。

先引入 repository 接口、schema 版本、字段校验、revision 和上一版快照，避免以后难以迁移。跨标签页检查不是数据库事务。正式后端接入时本地同步接口需要改为异步应用服务；3D 保持纯 props 接口。

## D004：选择 PostgreSQL + Prisma 作为后续唯一 ORM

关系数据适合长期演化，Prisma 类型和迁移工具便于维护。当前只在架构文档规划模型，未安装 Prisma、未连接数据库，不添加无实际作用的假 API。正式接入时先设计并验证迁移、所有权和导出/恢复流程。

## D005：不替用户命名

五颗示例只有外观，无用户名字、人生日期或虚构记忆；用 `isDemo` 明确区分。名称可为 `null`，显示「未命名草稿」。编辑保存后示例转为用户星球，介绍默认清空示例说明，避免把演示文字混入用户故事。

## D006：独立路由与阅读档案

`/planet/[id]` 是可直接访问的页面。3D 负责导航，档案承载正文和表单；没有把文字挂在球面。没有 WebGL 时可通过原生链接访问。进入先飞行再淡入；返回目前恢复镜头位置，没有反向飞离，留待体验迭代。

## D007：先测真实数据风险

第一轮使用 Node 内建测试，集中校验日期边界、冲突、配额、损坏数据、引用完整性，避免写复刻组件实现的浅层测试。`--test-isolation=none` 适配当前禁止创建测试子进程的 sandbox；不削弱断言。测试 10/10 通过。浏览器行为必须另外做真实环境验收，不能由纯函数测试推断通过。

## D008：安装与构建阻碍要保留证据

两次联网提权操作均在执行前被自动审批服务拒绝：HTTP 404，审批模型 `codex-auto-review` 不在配置账号组。用户授权重试后仍相同。普通 npm 安装尝试日志显示 `ECONNREFUSED`，已停止重试。没有更改网络代理或绕过审批。没有 lockfile，也没有构建成功证据。后续会话优先恢复依赖环境并完成验证，不能在记录中改写为「已通过」。
