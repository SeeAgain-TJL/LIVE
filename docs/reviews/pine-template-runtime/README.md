# Pine Forest · 画质与性能定版

同一台 Intel Graphics / ANGLE D3D11、Chrome 156、1440×900 窗口，生产构建。修改前是 `63865d7`，修改后是 `53d2f14`。保留原低/中/高及 70/80/100% 内部分辨率；每档各一个全新浏览器会话、同一套 42 秒 W 与段间鼠标转向，未修改相机坐标。实际行走受碰撞和帧时间影响，路线有小幅偏差。本机资源路径和 OS 缓存，不代表跨网冷下载。

| 档位 | 修改前平均 FPS / P95 | 修改后平均 FPS / P95 | 修改后首就绪 / 初始补齐 |
| --- | --- | --- | --- |
| 低 70% | 58.48 / 17.1ms | 60.05 / 16.9ms | 4.58 / 7.19s |
| 中 80% | 60.06 / 16.9ms | 60.07 / 16.8ms | 4.49 / 7.43s |
| 高 100% | 34.70 / 50.0ms | 35.09 / 34.8ms | 5.63 / 7.42s |

低档满足目标；中档接近显示器的 60Hz 上限；高档保留更细源网格，面向更强硬件。单次 A/B 表明没有明显性能退化，不将轻微 FPS 差异归因于具体优化，也不保证所有路线、机器或长期热稳定都达到该数字。

[切档与边缘实走](switches-boundary.json)：默认不带参数时是低档 70%，没有自动升高画质；低→中→高→低后实际发生 GPU 缓冲与纹理删除，重新进入低档没有残留 pine_04 中档资源。用真实 W 输入从 x=89 走到 x=99.49965 停在原边界前，没有开放补景行走范围。

[上下文恢复](context-recovery.json)通过显式丢失、提示、重新加载；[代表废墟边界](ruin-collision.json)通过。三档路线有分区、批次及材质释放记录，无捕获资源/页面错误、上下文丢失或档案读写。
